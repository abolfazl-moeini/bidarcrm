#### 2. `deploy/nginx.conf.template` ([B4])
* **Fix two NGINX bugs in the `/lead-capture` exemption:**
  1. NGINX `add_header` directives in a child `location` **drop all `add_header` directives inherited from `server`**. Any `location` adding `Content-Security-Policy "frame-ancestors *;" always;` must repeat `X-Content-Type-Options`, `Referrer-Policy`, and `Permissions-Policy`.
  2. `try_files $uri $uri/ /app/index.html;` performs an internal redirect into `location /app/`, which **re-applies `X-Frame-Options: SAMEORIGIN`**. Serve `/app/index.html` directly inside `location ~ ^/(app/)?lead-capture(/|$)` via `try_files /app/index.html =404;` (because `=404` is the fallback, NGINX serves `/app/index.html` in the same location without switching to `/app/`).
* **Preserve leading `^/` on blocked directories:** Keeping `location ~* ^/(application|data|custom|vendor|logs|...)/` is mandatory—removing `^/` would break `/client/custom/modules/bidar-theme/...`.
* **Include all actual `public/` PHP entrypoints & sub-apps:** Inspection of `engine/public/` shows `index.php`, `oauth-callback.php`, `api/v1/index.php`, `api/v1/portal-access/index.php`, `install/index.php`, `portal/index.php`, `portal/oauth-callback.php`, and `oauth/index.php`. Allowlist only these explicit `.php` paths (returning `404` for all other `\.php$`, plus using `location ^~ /app/` and `location ^~ /client/` so PHP never runs under `/app/` or `/client/`), and add `location /portal/`, `location /oauth/`, and `location /api/v1/portal-access/` alongside `/api/v1/` and `/install/`.
* **Handle `GET /` + `?entryPoint=` cleanly:** Because `engine/public/` contains `index.php` and no `index.html`, `location / { try_files $uri $uri/ /app/index.html; }` hits `public/index.php` on `GET /`. In `location = /`, handle `if ($arg_entryPoint != "") { rewrite ^ /index.php last; }` first, then serve `/app/index.html` (`try_files /app/index.html =404;`) if `/` is intended for the React SPA.
